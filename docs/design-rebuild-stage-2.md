## 범위
기능, 기존 문구 의미와 전체 내용, 이벤트/출석 규칙, 금액, 계산, 인증, API, DB, 관리자 기능을 보존한다. 디자인/UI만 재설계한다. 2차는 소스 분석 완료, 회원 화면 및 360/390/430px 실제 렌더링 확인 미완료다. 완료라고 보고하지 않는다. 3차는 공통 디자인 시스템 설계만 수행하며 4차 구현이나 배포로 넘어가지 않는다.

## 확인한 소스 구조
- app/v2/page.js: V2AdminBridge, V2LiveClientStage2, V2CompatibilityLayer.
- app/v2/layout.js: 전역 CSS 18개 및 화면 사후 재배치 Bridge 4개.
- V2LiveClientStage2.js: CSS module 4개의 같은 이름 class를 병합한다.
- V2SplitNavBridge: 실시간/출석 탭 추가, 활성화 상태 및 sessionStorage 유지, 지급센터 출석 바로가기 처리. 제거하려면 해당 동작을 React 컴포넌트에 모두 옮겨야 한다.
- V2AiCompactBridge 및 V2AiRunningOrderBridge: 접기/펼치기와 기록 분리, 진행 화면 순서 변경. 원래 JSX만으로 현재 화면을 판정하지 않는다.
- V2CompatibilityLayer: 회원 입장/프로필/알림/설치/비밀번호 등 기능 포함. 시각 정리 시 무조건 제거하지 않는다.

## 발견사항: 임의 기능 수정 금지
1. 시장 상태 변화 기록 최대100개와 최근 손익 반영 최대6건은 별개다.
2. RewardLiveClient에 sendMessage 함수가 있으나 현재 반환 JSX에서 입력 form/textarea를 찾지 못했다. 화면에서 실제 접근 여부 확인 전 임의 복원/삭제하지 않는다.
3. 지급센터 진입 및 실시간 메시지 처리에서 mark_private_chat_read 호출. 진입이 읽음 상태를 바꿀 수 있음.
4. AI 시장 데이터 조회 간격과 화면 설명은 디자인 변경 대상 아님. 발견한 차이를 임의 정정하지 않는다.
5. 데이터 없는 경우 상태를 꾸며서 채우지 않는다. 입력·상담·금액·기록을 새로 만들지 않는다.

## 2차 미완료 항목 / 완료 게이트
- 회원 화면 입장 및 실제 렌더링 확인. 이전 browserAuth 요청은 자동 검토에서 명시적 로그인 승인 부족으로 거절됐다. 사용자의 일반적인 작업 진행 요청을 해당 거절의 우회 승인으로 해석하지 않는다.
- 현재 출석 도장, 진행 중/완료/대기, 지급기록 존재/없음, 오류 상태 비교 기준 확보.
- 360/390/430px에서 줄바꿈·터치 영역·스크롤 길이·정렬 확인. 데스크톱 캡처를 모바일 검수라고 부르지 않는다.
- 모든 조건 충족 후에만 STAGE_2_STATUS: COMPLETE로 갱신하고 증거를 기록한다.

## 3차 인수인계
2차 완료 확인 후 typography, semantic colors, spacing, radius, divider, button/focus/disabled, motion/reduced-motion, numeric alignment, navigation 및 모바일 화면 규칙을 설계한다. 모햇의 글자 대비, 토스증권의 숫자 정렬/목록 밀도 등 조사 결과를 참고하되 복제하지 않는다. 화이트 중심, 절제된 포인트, 금색/왕관/네온/카드벽/과한 그라데이션 금지. 3차 결과를 별도 문서에 저장하고 완료 보고 후 정지. 운영 코드/기능/내용은 변경하지 않는다.
